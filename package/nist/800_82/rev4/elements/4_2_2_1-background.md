Different types of OT system data can be found in the OT network, such as control data (e.g., setpoints, recipes, interlocks, alarm settings), process data (e.g., sensor readings, batch records, quality measurements), and identity and access data (e.g., accounts, roles, remote access logs). Additionally, information related to the OT system data can be found on the IT network, such as engineering data (e.g., Piping and Instrument Drawings [P&IDs], electrical diagrams, robot programs, operating manuals, Programmable Logic Controller [PLC]/Distributed Control System [DCS] code, firmware, network diagrams), asset data (e.g., inventories, firmware versions, vulnerability/patch status), environmental data (e.g., emission records, compliance evidence), and maintenance data (e.g., work orders, service reports).

OT data needs to be classified based on its impact on the organization due to loss or modification. Some of the criteria to be considered include the safety/operational impact if the data is altered or lost, how difficult recovery would be, who currently has access to the data, whether the data is exported and to whom, and whether an adversary reviewing the data would gain an understanding of the organization’s system or be able to use it to help plan a campaign. Data control considerations can include data access, handling rules (e.g., storage, transmission, access, retention), sharing with vendors/third parties, and compliance requirements. These considerations apply to data at rest and in transit.
